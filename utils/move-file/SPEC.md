# Спецификация: move-file

| Метаданные | Значение |
| --- | --- |
| **Версия** | 1.0.0 |
| **Статус** | ✅ Реализовано |
| **Платформа** | Sherpa RPA 1.4.4 |
| **Тип** | Утилита перемещения файлов |

## 1. Назначение

Утилита `move-file` предназначена для надежного перемещения файла из источника в целевую папку с автоматическим созданием недостающих директорий. Решает проблему падения RPA-сценариев при попытке переместить файл в несуществующий путь или при ошибках прав доступа.

В случае возникновения ошибок детальное логирование и структурированный вывод позволяют получить понятное описание проблемы без прерывания работы родительского робота. По умолчанию файл перезаписывается, если он уже существует в целевой папке. Исходный файл удаляется только после гарантированного подтверждения успешной записи копии в целевую папку.

## 2. Контекст и проблематика

В процессе автоматизации часто возникает необходимость переместить обработанный файл из временной папки в архивную структуру (например, по датам: `D:\archive\2026\09\`). Стандартные средства перемещения падают с ошибкой, если целевая директория не существует.

Кроме того, использование простого блока "Переместить файл" без проверок может привести к потере данных, если операция прервется на полпути, или к неочевидным системным ошибкам при превышении лимита длины пути Windows (256 символов).

Данная утилита инкапсулирует проверку и создание пути, валидирует его длину, а операцию перемещения реализует по безопасному паттерну "Копирование → Проверка → Удаление". В случае проблем она возвращает вызывающему процессу стандартизированный результат, предотвращая нештатное падение робота и гарантируя сохранность данных.

## 3. Контракт данных

### 3.1 Входные аргументы (In)

| Имя | Тип | Обязательный | По умолчанию | Описание |
| --- | --- | --- | --- | --- |
| `source_file_path` | String | ✅ Да | — | Полный путь к исходному файлу (абсолютный или относительный). Пример: `C:\data\report.xlsx` |
| `destination_folder_path` | String | ❌ Нет | `''` (пустая строка) | Путь к целевой **папке**. Если не указан (или пуст), файл будет перемещен в корневую рабочую директорию сценария робота. |

### 3.2 Выходные аргументы (Out)

| Имя | Тип | Описание |
| --- | --- | --- |
| `result` | HashTable | Объект, содержащий результаты операции. |

**Структура HashTable `result`:**

| Ключ | Тип | Описание |
| --- | --- | --- |
| `is_success` | Boolean | `True` если перемещение выполнено успешно, `False` в случае ошибки. |
| `status_message` | String | Человекочитаемое сообщение: `"OK"` или текст перехваченной ошибки. |
| `new_file_path` | String | Абсолютный путь к перемещенному файлу (пустая строка при ошибке). |

## 4. Алгоритм работы

**Шаг 1: Инициализация и логирование**

- Запись в лог: `"[INFO]:[move-file]: Запуск обработки source={source_file_path}, destination={destination_folder_path}"`
- Создание HashTable `result` и заполнение дефолтными значениями:
  - `is_success = $False`
  - `status_message = 'Неизвестная ошибка'`
  - `new_file_path = ''`

**Шаг 2: Валидация источника (Критический шаг)**

- Проверка 1: `source_file_path` не является пустым/null.
  - Если пустой: Вызвать исключение `"Путь к источнику не может быть пустым"`.
- Проверка 2: Файл по пути `source_file_path` физически существует.
  - Если не существует: Вызвать исключение `"Исходный файл не найден: {source_file_path}"`.
- *Действие при исключении*: Перехватить исключение, записать его текст в `result.status_message` и перейти к Шагу 7.

**Шаг 3: Формирование итогового пути**

- Извлечь имя файла из `source_file_path`.
- Если `destination_folder_path` пустой, использовать рабочую директорию робота.
- Склеить путь: `final_file_path = destination_folder_path + имя_файла`.

**Шаг 4: Проверка длины пути**

- Условие: Длина `final_file_path` > 256 символов.
- Действие:
  - `result.status_message = "Превышен лимит длины пути: {фактическая длина}"`
  - Переход к Шагу 7.

**Шаг 5: Обеспечение целевой папки**

- Проверить существование `destination_folder_path`.
- Если не существует:
  - Try: Создать директорию (включая все промежуточные).
  - Catch: Перехватить исключение.
    - `result.status_message = "Ошибка создания директории: {текст исключения}"`
    - Переход к Шагу 7.

**Шаг 6: Операция перемещения (паттерн "Копирование → Проверка → Удаление")**

Для гарантии сохранности данных используется безопасный трехэтапный паттерн:

**6.1 Копирование файла**

- Try: Скопировать файл из `source_file_path` в `final_file_path` (с перезаписью).
- Catch: Перехватить исключение.
  - `result.status_message = "Ошибка копирования файла: {текст исключения}"`
  - Переход к Шагу 7.

**6.2 Проверка успешности копирования**

- Условие: Файл по пути `final_file_path` физически существует.
- Если не существует:
  - `result.status_message = "Файл не был создан в целевой папке после копирования"`
  - Переход к Шагу 7.

**6.3 Удаление исходного файла**

- Try: Удалить файл по пути `source_file_path`.
- Catch: Перехватить исключение.
  - `result.status_message = "Файл скопирован успешно, но не удалось удалить исходный файл: {текст исключения}. Новый путь: {final_file_path}"`
  - **Важно**: В этом случае `is_success = $False`, но `new_file_path` заполнен (файл уже в целевой папке).
  - Переход к Шагу 7.

**6.4 Финализация успеха**

- Если все три этапа прошли успешно:
  - `result.is_success = $True`
  - `result.status_message = "OK"`
  - `result.new_file_path = final_file_path`

**Шаг 7: Завершение и логирование**

- Запись в лог: `"[INFO]:[move-file]: Завершение обработки. Успех={result.is_success}, Сообщение={result.status_message}"`
- Возврат HashTable `result` вызывающему процессу.

## 5. Обработка ошибок

| Сценарий | is_success | status_message |
| --- | --- | --- |
| Пустой `source_file_path` | `$False` | `"Путь к источнику не может быть пустым"` |
| Исходный файл не найден | `$False` | `"Исходный файл не найден: {path}"` |
| Превышена длина пути (>256 символов) | `$False` | `"Превышен лимит длины пути: {N}"` |
| Не удалось создать директорию | `$False` | `"Ошибка создания директории: {текст исключения}"` |
| Ошибка копирования | `$False` | `"Ошибка копирования файла: {текст исключения}"` |
| Файл не создан в целевой папке | `$False` | `"Файл не был создан в целевой папке после копирования"` |
| Ошибка удаления источника | `$False` | `"Файл скопирован успешно, но не удалось удалить исходный файл: {текст исключения}. Новый путь: {final_file_path}"` |
| Любая непредвиденная ошибка | `$False` | `"Ошибка выполнения задачи - {текст ошибки}"` |
| Успешное перемещение | `$True` | `"OK"` |

## 6. Критерии приемки (Definition of Done)

- [ ] Утилита импортируется в Sherpa RPA 1.4.4 без ошибок зависимостей.
- [ ] Успешно перемещает файл в новую, ранее не существовавшую вложенную структуру папок.
- [ ] Корректно перемещает файл в рабочую директорию робота, если `destination_folder_path` не передан.
- [ ] Возвращает `is_success=$False` и внятное сообщение при превышении длины пути 256 символов.
- [ ] Возвращает `is_success=$False` при отсутствии исходного файла.
- [ ] Исходный файл гарантированно удаляется только после успешного появления файла в целевой папке.
- [ ] При ошибке удаления источника возвращается частичный успех: `is_success=$False`, но `new_file_path` заполнен.
- [ ] Логи содержат четкие маркеры `[INFO]:[move-file]`.
- [ ] Выходной HashTable `result` строго соответствует контракту данных.
